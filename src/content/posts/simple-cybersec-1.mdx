## CVE（Common Vulnerabilities and Exposures）

念過資安領域的都知道，我們有那麼多的名詞以及技術，但說到資安人一定會需要知道的名詞之一，那肯定就是非 CVE 莫屬；而這個字呢，最直截了當的解釋其實就是 **「漏洞」**。

### 歷史背景

稍微闡述一下歷史，CVE 這個詞最早其實是從 1999 年的 1 月由一間美國名為 MITRE 公司的 David E. Mann 與 Steven M. Christey 在 Purdue University 所舉辦的一場研討會所發表並提出的一個漏洞命名機制構想。

隨後獲得社群的支持後，於 1999 當年的 9 月正式公開發布上線，成為目前全球共同使用的漏洞識別標準。

### 核心意義

那漏洞種類那百百種，不同國家不同地域的人要怎麼有效的識別這些漏洞是甚麼？並且自己遇到的漏洞到底跟別人遇到的一不一樣，到底是不是同一個漏洞呢？

就好比如：
* 廠商 A 可能稱某漏洞為「Buffer Overflow in XYZ」
* 廠商 B 可能稱同一漏洞為「XYZ Remote Execution Bug」

一個說 A 一個說 B，結果到頭來大家談論的是同一個漏洞，卻不知道彼此在講同一件事，而導致資訊交流困難，難以溝通。

而 CVE 的做法就是給每個公開漏洞一個唯一的官方編號，可以把它想成漏洞世界的 **「身分證字號」**。它不負責告訴你怎麼修，也不一定完整描述攻擊細節；它最重要的功能是讓全世界所有人談論漏洞時能使用同一個 **「共同語言」**。

如果沒有 CVE，供應商公告一套說法、掃描工具一套編號、新聞媒體另一套叫法，團隊在溝通時會非常混亂。一旦有了 CVE，大家至少先對齊：「我們現在討論的是同一個漏洞」。

> CVE 是全球漏洞標準的「身分證字號」，能夠有效識別以及做到資訊交換的目的。

## CWE（Common Weakness Enumeration）

但有了 CVE 這個身分證字號，其實還不夠。因為你會接著問：這個漏洞「本質上」是基於哪種原因所造成的？CVE 只能方便識別這個漏洞本人是誰，但沒辦法回答這個漏洞是被歸類在哪一類別當中，也就是說，無法跟你說明不同 CVEs 之間到底有沒有關聯。因此接下來就很快有了 CWE 的這個名詞的出現啦~

### 歷史背景

早在 MITRE 建立完 CVE 時，就已經開始研究漏洞背後的共通成因，例如 Buffer Overflow、SQL Injection 等等漏洞。

於 2005 年 MITRE 在 NIST 的 SAMATE（Software Assurance Metrics and Tool Evaluation）計畫中整理出名為 PLOVER 的軟體弱點研究成果，建立了大量真實漏洞與共通弱點的對應關係。之後在 2006 年正式發布第一版 CWE。

### 核心功能
 
你可以把 CVE 想成一場事故，CWE 想成事故原因分類。例如某次漏洞是因為輸入驗證不足、某次是權限控管錯誤、某次是記憶體邊界處理不當。這些類型都不是單一事故，而是可能重複出現在不同產品、不同年份、不同團隊的身上。

所以如果 CVE 幫你「找到哪裡壞了」，那 CWE 就是在提醒你「為什麼一直壞在同一種地方」。對 IT 團隊來說，CWE 的價值在於能把修補從「單點救火」提升到「系統性預防」。

For example:
| CWE     | 弱點類型                    |
| ------- | -------------------------- |
| CWE-79  | Cross-Site Scripting (XSS) |
| CWE-89  | SQL Injection              |
| CWE-787 | Out-of-Bounds Write        |
| CWE-798 | Hard-coded Credentials     |

> CWE 不是某個特定漏洞，而是「漏洞背後的弱點類型」。

## CPE（Common Platform Enumeration）

接著還有最後一個問題：你掃描到一個漏洞 ID，OK 很好，那它到底跟你哪一台主機、哪個套件、哪個版本有關？這樣才能精準判斷這個 CVE 到底應該如何被修復，像是升級到特定版本等等。

那這時候就需要靠 CPE（Common Platform Enumeration）來做到。

### 核心功能

CPE 的角色比較像「標準化的產品名稱座標」，用來精準描述：
- 哪家廠商
- 哪個產品
- 哪個版本。

想像你在資產盤點時只寫「Apache」或「OpenSSL」，其實太模糊；而 CPE 的設計目的，就是讓機器能判斷「這則漏洞情報是否命中我的資產」。

所以在實務上來說的策略會是：

資產（可被映射成 CPE）  
→ 對到漏洞公告（CVE）  
→ 再看弱點類型（CWE）做修補優先與長期治理

## 總結

如果要用一句話總結這三個名詞，我會這樣記：

> **CVE 是「事件 ID」，CWE 是「原因類型」，CPE 是「受影響對象的標準描述」。**

它們不是互斥關係，而是剛好拼成一個可運作的漏洞管理語言。但凡缺少了其中之一，整個流程都會缺一角：不是說不清楚、就是對不準資產、或是修完還會再犯。當你看到一個 CVE，不會只停留在「升級版本」；而是你會開始追問：這個問題屬於哪種 CWE？我們專案裡有沒有同類型的風險？
